代理规则 全局 0

公网请求进 Caddy 后按「域名 → 路径」从上到下匹配，命中第一条就转发到对应上游； 一条都不命中就返回自定义 404。顺序即优先级。
🔍 模拟匹配 —— 输入路径看它命中哪条规则（只是推算，不发请求）
填好后点「模拟」
匹配规则：从上到下，第一条命中即停止。四种条件可组合： 域名（Host）、路径前缀、请求方法、来源 IP（CIDR）。
路径前缀 自动补通配：/demo 实际匹配 /demo*（含 /demo/xx 和 /demox）。
剥离前缀：勾上后 /demo/xx 转发给上游时变成 /xx（很多应用不认子路径，必须勾）。
上游：127.0.0.1:8096 / http://192.168.1.10:5000 / https://nas.local:5001 都可以。

非 HTTP 服务（SSH / TCP / UDP）

本面板只代理 HTTP/HTTPS。数据库/SSH 的原生端口挂到 HTTP 上游一律 502（协议不同），三条正路：
  1. Web 外壳：ttyd / wetty / code-server / Adminer / phpMyAdmin，用规则指向它们的端口。
  2. cloudflared access（命名隧道）：在 Cloudflare 后台给该隧道加 ssh.yourdomain.com → ssh://localhost:22， 客户端装 cloudflared 后 cloudflared access ssh --hostname ssh.yourdomain.com，再 ssh user@ssh.yourdomain.com。
  3. Tailscale / WARP：点对点，不经过 Cloudflare。

          常见原因是上游端口写错、或路径前缀不匹配。

Cloudflare 字段填什么为什么

        
子域 / 域app + 你的域名最终地址 = app.你的域名；想用根域名则子域留空

        
路径留空整个域名交给 Caddy，再由本页规则分流

        
服务 · 类型HTTP本地 Caddy 是明文 :8080，选 HTTPS 必然 502

        
服务 · URL127.0.0.1:8080必须指向 Caddy：不是面板 8090，也不是业务端口。
（若某个出口想绕过 Caddy 直连服务，把该出口的「隧道指向」改成那个端口即可）

        
附加设置一般不动只有老式自签 HTTPS 上游才需要「TLS → 无 TLS 验证」

      


      
    
        
  • 保存后 Cloudflare 会自动建 CNAME 指向 <隧道ID>.cfargotunnel.com，不要手工加 A 记录、也不要指向自己服务器 IP。
    • 
        
  • 多个出口怎么分工：常见做法是「命名隧道当主用 + 快速隧道当备用/临时分享」；或者「A 账号隧道给家里服务，B 账号隧道给对外服务」。
          所有命名出口都指向 8080 时，Cloudflare 那边靠主机名区分，本页靠规则的「域名」列区分，互不冲突。
    • 
        
  • 每个出口的 metrics 端口要不同（或都留空），撞了会启动失败。
    • 
        
  • 排错口诀：页面 1033 = 那条隧道没有连接器（看对应出口的日志）；502 = cloudflared 到了但 Caddy 没应答（查本地 8080）；404 = 到了 Caddy 但没匹配规则。
    • 
        
  • token 等于半把钥匙：别贴到公开地方；怀疑泄露就去隧道页 刷新 token 再回来重贴。
